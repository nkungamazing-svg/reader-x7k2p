# คลังบทแปลส่วนตัว (PWA)

เว็บแอปอ่านนิยายบนมือถือสำหรับบทแปลที่นำเข้าเป็นไฟล์ JSON ทำงานแบบ static ทั้งหมด ไม่มี build ไม่มี dependency และไม่มี API key ข้อมูลบทแปล ค่าการอ่าน และคู่ชื่อตัวละครเก็บอยู่ใน IndexedDB ของเบราว์เซอร์บนเครื่องนั้น ไม่มีโค้ดใดอัปโหลดเนื้อหาออกไปข้างนอก

เอกสารนี้จัดเป็นหมวดตามการใช้งาน ถ้าเพิ่มฟีเจอร์ใหม่ให้เติมในหัวข้อที่ตรงกับหมวดนั้น (หรือเพิ่มหัวข้อย่อยในหมวดที่ใกล้ที่สุด) ไม่ใช่ต่อท้ายไฟล์

---

## 1. เริ่มใช้งาน

### 1.1 ติดตั้งบน iPhone

1. โฮสต์โฟลเดอร์นี้ผ่าน HTTPS (ดู [5.2 GitHub Pages](#52-github-pages))
2. เปิด URL ใน Safari แล้วกดปุ่มแชร์ → **เพิ่มไปยังหน้าจอโฮม**
3. เปิดแอปจากไอคอน แล้วเลือก **นำเข้าไฟล์สำรอง**
4. เลือกไฟล์ JSON ที่ได้จากปุ่ม **สำรอง/ย้ายข้อมูล** ของส่วนขยาย แล้วเลือก **รวมกับข้อมูลเดิม** หรือ **แทนที่บทและตารางคำอ่าน**

หลังเปิดครั้งแรกให้รอให้เว็บโหลดครบก่อนใช้งานออฟไลน์ ไฟล์แอป (`index.html`, `app.js`, `style.css`), manifest, ไอคอน, ฟอนต์ และ `characters.json` จะถูกเก็บใน Cache Storage ส่วนบทแปล ตารางคำอ่าน และค่าตั้งค่าอยู่ใน IndexedDB ของอุปกรณ์

### 1.2 รูปจากเว็บต้นทาง

รูปในบทและรูปตัวละครโหลดจากเว็บต้นทางได้เมื่อเปิดสวิตช์ **โหลดรูปจากเว็บต้นทาง** (ค่าเริ่มต้นเปิด) จึงต้องมีอินเทอร์เน็ต และเบราว์เซอร์จะเรียกรูปโดยตรงโดยไม่ส่ง referrer เมื่อปิดสวิตช์จะไม่มีการเรียกออกเน็ตเลย ส่วนรูปที่ฝังมาเป็น `data:image` ในไฟล์สำรองยังแสดงได้ตามปกติ หากโหลดรูปไม่สำเร็จจะมีปุ่ม **ลองใหม่**

### 1.3 การอัปเดตเวอร์ชันบนเครื่อง

ไฟล์เปลือกแอปถูกดึงจากเครือข่ายก่อนและเก็บ cache ไว้ใช้ตอนออฟไลน์ (ฟอนต์และไอคอนยังใช้ cache ก่อนเพื่อประหยัดเน็ต) แอปเรียกตรวจ service worker ใหม่ทุกครั้งที่กลับเข้าหน้าและทุก 5 นาทีระหว่างเปิดอยู่ ถ้ามีเวอร์ชันใหม่จะโหลดหน้าใหม่ให้หนึ่งครั้งเอง (กันลูปด้วย `sessionStorage`) เลขเวอร์ชันที่หน้าจอเปิดแอปและท้ายหน้าตั้งค่าบอกได้ว่าเครื่องได้รับรุ่นไหนแล้ว ส่วน GitHub Pages ใช้เวลาสร้าง 1–3 นาทีหลัง push และดูสถานะได้ที่แท็บ Actions

## 2. การอ่าน

### 2.1 สองโหมดการอ่าน

ค่าเริ่มต้นคือ **เลื่อนต่อเนื่อง** และกดปุ่ม **โหมด** ที่แถบล่างเพื่อสลับเป็น **พลิกหน้า** ได้ทุกเมื่อ (หรือเลือกที่ *ตั้งค่าการอ่าน → การอ่าน → โหมดการอ่าน*)

- **เลื่อนต่อเนื่อง** — เลื่อนอิสระ แตะย่อหน้าเพื่อเริ่มอ่านออกเสียงได้
- **พลิกหน้า** — แตะขอบซ้าย/ขวาของจอหรือปัดเพื่อเปลี่ยนหน้า แตะกลางจอเพื่อซ่อนหรือเปิดแถบเครื่องมือ พลิกเกินหน้าสุดท้ายของตอนจะเปิดตอนถัดไปให้ทันที (ย้อนกลับจากหน้าแรกของตอนจะไปหน้าสุดท้ายของตอนก่อนหน้า) ใช้การแตะจอสำหรับเปลี่ยนหน้าแทนการแตะอ่านออกเสียง

### 2.2 แถบล่างและเลขหน้าในโหมดพลิกหน้า

แถบล่างมี 7 ปุ่มพร้อมป้ายกำกับใต้ไอคอน ได้แก่ **ย้อน · ฟัง/พัก · ข้าม · หยุด · โหมด · ซ่อน · ตั้งค่า** ไอคอนวาดด้วย SVG ในปุ่มเอง (ไม่ใช่ตัวอักษร ⏮ ▶ ⏭ ■ 📄 ⤢ ⚙ ที่ฟอนต์เครื่องอาจแปลงหน้าตาไม่เหมือนกัน) และแต่ละปุ่มสูง 52px แตะง่าย ส่วนปุ่มนำเข้าที่หัวจอเป็นเครื่องหมาย + ที่วาดด้วย CSS จึงไม่เอียงตามฟอนต์

ในโหมดเลื่อนต่อเนื่องมีเส้นความคืบหน้าบาง ๆ ที่ขอบบนจอ (เรืองแสงสีเดียวกับปุ่มหลัก) พร้อมป้าย % ที่โผล่ขึ้นมุมขวาบนชั่วครู่ขณะเลื่อนอ่าน แล้วจางหายเองในราว 1.4 วินาที

ในโหมดพลิกหน้ามีแถบเลขหน้าและเปอร์เซ็นต์ของตอน พร้อมเส้นความคืบหน้าบาง ๆ ที่ขอบบนจอ พื้นที่อ่านถูกคำนวณให้สิ้นสุดเหนือแถบเลขหน้าและแถบเมนูลอยเสมอ (จองพื้นที่ไว้ตลอด แม้ซ่อนเมนู) ข้อความจึงไม่ถูกเมนูทับและเลขหน้าไม่กระโดดเมื่อเปิด/ปิดแถบ รูปประกอบในบทถูกจำกัดความสูงไว้ที่ราว 62% ของพื้นที่อ่านหนึ่งหน้า (พร้อมตัดระยะขอบรอบรูปและย่อหน้ารูปเดี่ยว) เพราะรูปแตกข้ามหน้าไม่ได้ ถ้าปล่อยให้สูงเต็มหน้าตัวจัดหน้าจะดันรูปไปหน้าถัดไปและทิ้งหน้านั้นว่างเปล่า รูปในบทโหลดแบบ eager (ไม่ lazy) เพื่อให้วัดความสูงได้จริงก่อนแบ่งหน้า และหัวบท (ชื่อเรื่อง + ชื่อตอน) ถูกตั้ง `break-inside: avoid` ไม่ให้ถูกตัดแยกไปคนละหน้า

ถ้าข้อความหรือแถบความคืบหน้าชนติ่งหรือกล้องหน้า (เช่น iPhone XR) ให้เพิ่ม **ระยะขอบบน (กันติ่ง/กล้อง)** ในหน้าตั้งค่า ระบบเว้น safe area ของจอไว้ให้แล้ว และสไลเดอร์นี้เผื่อเพิ่มได้อีกสูงสุด 90px

### 2.3 คำแนะนำการแตะจอ

ครั้งแรกที่เปิดโหมดพลิกหน้า แอปจะแสดงไกด์เรืองแสงที่ขอบซ้าย/ขวา (ปัดหรือแตะเพื่อเปลี่ยนหน้า) พร้อมป้ายกลางจอ "แตะกลางจอ · เปิด/ซ่อนเมนู" แล้วจางหายเองในราว 4 วินาที หรือหายทันทีเมื่อแตะครั้งแรก ทุกครั้งที่พลิกหน้าจะมีแสงวาบที่ขอบด้านที่เพิ่งพลิกเป็นสัญญาณว่ากดติด ปิดไกด์นี้ได้ที่ *ตั้งค่าการอ่าน → การอ่าน → แสดงคำแนะนำการแตะจอ*

### 2.4 ซ่อนแถบเครื่องมือ

ปุ่ม **ซ่อน** (ไอคอนลูกศรชี้ลง) บนแถบล่างซ่อนแถบหัวเรื่องและแถบเครื่องมือได้ทั้งสองโหมด (อีกทางหนึ่งคือแตะกลางจอในโหมดพลิกหน้า) ระหว่างที่ซ่อนอยู่ การแตะจอหนึ่งครั้งจะเรียกแถบกลับมาโดยไม่กระตุ้นการอ่านออกเสียง และการปัดเพื่อเลื่อนอ่านยังทำงานปกติ ป้ายบนปุ่มยังเป็น “ซ่อน” และข้อความช่วยอ่าน (title/aria-label) จะเปลี่ยนเป็น “แสดงแถบเครื่องมือ” เมื่อแถบถูกซ่อนอยู่

### 2.5 ธีม

นอกจาก **มืด / สว่าง / ซีเปีย / ดำสนิท** มีธีมสำหรับอ่านนาน ๆ อีกสามแบบ: **🌿 ถนอมสายตา** (พื้นเขียวอ่อนแบบ eye-care ตัวอักษรเขียวเข้ม ลดความจ้า), **🌤️ ฟ้าเทา** (เทาโทนเย็น กลางวันสบายตา) และ **🌆 พลบค่ำ** (มืดอุ่น คอนทราสต์ต่ำกว่าโหมดดำสนิท อ่านก่อนนอนสบายกว่า) สีแถบสถานะของเบราว์เซอร์เปลี่ยนตามธีมด้วย ทุกธีมบันทึกค่าไว้ใน IndexedDB และมีผลทั้งสองโหมด

### 2.6 ฟอนต์และขนาดตัวอักษร

iPhone ไม่ยอมให้เว็บติดตั้งฟอนต์เพิ่มเอง แอปจึงฝังฟอนต์ SIL OFL มาด้วย (Noto Sans Thai, Sarabun, Noto Serif Thai และทางเลือก "ฟอนต์ระบบ iOS") เลือกได้ที่ *ตั้งค่าการอ่าน → ตัวอักษร → ฟอนต์ข้อความ* เปลี่ยนแล้วระบบจัดหน้าใหม่และจำค่าไว้ ไฟล์สิทธิ์ฟอนต์อยู่ใน `fonts/OFL-*.txt` ขนาดตัวอักษร ระยะบรรทัด และความกว้างข้อความปรับได้ในกลุ่มเดียวกัน

### 2.7 รูปและอิโมจิในบท

รูปที่มีขนาดจริงเล็ก (ไม่เกิน 200×200 พิกเซล เช่นอิโมจิหรือสติกเกอร์) จะแสดงขนาดเท่าตัวอักษร (~1.4em) แทนภาพประกอบเต็มหน้า ส่วนรูปใหญ่ยังแสดงเป็นภาพประกอบตามปกติ ถ้าบทแปลแนบ `font-size` ที่ใหญ่ผิดปกติมาในสไตล์ ระบบจะตัดค่านั้นทิ้งเพื่อไม่ให้ตัวอักษรหรืออิโมจิตัวเดียวกินพื้นที่ทั้งหน้า

### 2.8 รายการบท (หน้าเลือกตอน)

เปิดด้วยปุ่ม ☰ ที่หัวจอ ระหว่างเปิดอยู่พื้นหลังจะถูกหรี่ให้มืดและเบลอ เพื่อไม่ให้ตัวหนังสือหน้าอ่านทะลุขึ้นมาอ่านได้ และฉากหลังนี้อยู่เหนือแถบหัวจอ/แถบล่าง/แถบเลขหน้าเสมอ (ปิดได้ด้วยการแตะนอกแถบ)

แถวแต่ละตอนเป็นรูปแบบเดียวกันทั้งรายการ: ช่องเลขบทด้านซ้าย ชื่อเรื่องบรรทัดเดียว (ตัดคำเกินด้วย …) และป้ายสถานะด้านขวา ("อ่านแล้ว" หรือเปอร์เซ็นต์ที่อ่านค้างไว้) ตอนที่ยังไม่อ่านไม่มีป้ายเพื่อให้รายการดูโล่ง แถบความคืบหน้าแบบบางอยู่ที่ขอบล่างของแถวและแสดงเฉพาะตอนที่อ่านค้างไว้ หัวข้อ Novel และ Arc ติดอยู่ด้านบนขณะเลื่อน และมีจำนวนตอน/จำนวนที่อ่านแล้วกำกับ เมื่อเปิดรายการแอปจะเลื่อนไปที่ตอนที่กำลังอ่านให้อัตโนมัติ

### 2.9 ไม่ให้แตะเลือกข้อความและไม่ให้ซูม

หน้าอ่านปิดการเลือกข้อความและการกดค้างเพื่อเรียกเมนูของ iOS (`user-select:none`, `-webkit-touch-callout:none`) จึงไม่มีแถบไฮไลต์สีฟ้าเวลากดค้าง เหลือเพียงการอ่าน การแตะย่อหน้าเพื่ออ่านออกเสียง และการแตะชื่อตัวละครเพื่อดูรูป

การซูมถูกปิดด้วย: `maximum-scale=1, user-scalable=no` ใน meta viewport, การบล็อก event `gesturestart`/`gesturechange`/`gestureend` และการเลื่อนนิ้วตั้งแต่สองนิ้วขึ้นไป (Safari บน iOS ไม่สนใจ `user-scalable=no` จึงต้องกันที่ event), `touch-action: pan-y` ที่ `html`/`body` และ `touch-action: manipulation` ที่ปุ่ม/สวิตช์ สำหรับช่องกรอกทุกช่องใช้ตัวอักษรอย่างน้อย 16px เพราะ iOS จะซูมเองเมื่อโฟกัสช่องที่ตัวอักษรเล็กกว่านั้น

## 3. ตัวละคร

### 3.1 การ์ดรูปตัวละคร

ชื่อตัวละครที่ส่วนขยายทำเครื่องหมายไว้ (ขีดเส้นใต้จุด ๆ ในบท) แตะได้บนมือถือ แตะแล้วมีการ์ดเล็ก ๆ ขึ้นจากด้านล่างพร้อมรูปของตัวละครนั้น ดึงรูปจาก Re:Zero Wiki ด้วยชื่อภาษาอังกฤษที่แนบมากับชื่อ (ถ้าไม่มีชื่อภาษาอังกฤษจะแจ้งว่าไม่พบ) รูปที่เคยเปิดแล้วถูกจำไว้ในเครื่องและแสดงได้ทันทีโดยไม่ต้องต่อเน็ต การดึงรูปทำงานผ่านสวิตช์ **โหลดรูปจากเว็บต้นทาง** และในโหมดพลิกหน้าการ์ดลอยอยู่เหนือแถบเลขหน้าและแถบเมนู (ไม่ทับปุ่ม) การ์ดปิดเองใน 10 วินาทีหรือปิดด้วยปุ่ม × / แตะที่อื่นบนหน้าจอ และถ้าเปิดรูปตัวละครใหม่ นาฬิกา 10 วินาทีจะเริ่มนับใหม่ทุกครั้ง (ไม่นับต่อจากรูปเดิม)

ในโหมดพลิกหน้า การแตะชื่อตัวละครจะเปิดการ์ดรูปแทนการพลิกหน้า (การปัดซ้าย/ขวายังเปลี่ยนหน้าได้ และแตะขอบจอนอกชื่อยังพลิกหน้าเหมือนเดิม)

### 3.2 ถ้าขึ้นว่าไม่พบชื่อทุกตัว

ถ้าไฟล์บทมีแต่ชื่อไทยและไม่มีชื่อภาษาอังกฤษ การ์ดจะเปิดช่องให้ตั้งชื่อครั้งแรก: พิมพ์ชื่อในวิกิ (เช่น `Otto Suwen`) หรือพิมพ์บางส่วนแล้วเลือกจากรายการที่ระบบค้นให้ (กดที่ชื่อแล้วระบบดึงรูปและจำคู่ชื่อไทย–อังกฤษไว้) ครั้งต่อไปแตะชื่อเดิมจะขึ้นรูปทันที ข้อมูลคู่นี้เก็บใน IndexedDB ของเครื่อง

### 3.3 นำเข้าตารางชื่อตัวละคร (กลอสซารี)

ถ้ามีไฟล์กลอสซารีของส่วนขยาย (รายการ `{ "src": "Otto Suwen", "dest": "อ็อตโต้" }`) กด *ตั้งค่าการอ่าน → อื่น ๆ → ตารางชื่อตัวละคร → นำเข้า JSON* ระบบจะจับคู่ `dest` (ชื่อไทย) เข้ากับ `src` (ชื่ออังกฤษ) ให้ทุกคำ แล้วแตะชื่อในบทจะขึ้นรูปได้ทันทีโดยไม่ต้องตั้งทีละตัว รายการที่ชื่อมีวงเล็บอธิบาย เช่น `ซู-โบ้(ซุบารุ)` จะถูกจับคู่ทั้งแบบมีและไม่มีวงเล็บ ปุ่ม **ล้าง** ลบตารางนี้ออก และจำนวนที่จับคู่ไว้แสดงใต้ปุ่ม

### 3.4 ดัชนีตัวละครจากหน้า Characters

หน้า [Characters](https://rezero.fandom.com/wiki/Characters) ของวิกิรวมตัวละครเกือบทั้งเรื่องไว้ในหน้าเดียว แต่ละคนมีรูป ชื่อหน้าวิกิ และสีพื้นการ์ดที่บอกฝ่าย/แคมป์ `tools/build-characters.py` ดึงหน้านั้นมาทำเป็น `characters.json` ที่ฝังไปกับแอป (และถูก precache โดย service worker) เวลาแตะชื่อ แอปหาจากดัชนีก่อน — ได้รูปทันทีโดยไม่ต้องค้นทีละชื่อ และการ์ดมีเส้นขอบสีเดียวกับฝ่ายของตัวละครนั้นพร้อมชื่อฝ่ายใต้รูป ถ้าไม่พบในดัชนีจึงค่อยยิงค้นวิกิแบบเดิม

จุดที่ต้องระวังในการสร้างดัชนี:

- หน้านั้น lazy-load รูป HTML ที่ได้จึงมักมีแต่ GIF 1×1 เป็น placeholder สคริปต์จึงอ่านชื่อไฟล์จาก `data-image-name` แล้วแปลงเป็น URL จริงผ่าน API `imageinfo` (ทีละ 40 ไฟล์) และทิ้งรายการที่ไม่มีรูปจริง
- ชื่อที่แสดงบนการ์ดอาจซ้ำกัน (เช่น `Eridna` แสดงชื่อว่า "Echidna") แอปจึงให้ **ชื่อหน้าวิกิมีสิทธิ์ก่อนชื่อที่แสดง**
- ถ้าอยากอัปเดตข้อมูลใหม่ให้รัน `python3 tools/build-characters.py` แล้ว bump เวอร์ชันตามปกติ

### 3.5 การจับคู่รูปให้แม่นขึ้น

เดิมระบบใช้ผลการค้นหาอันดับแรกของวิกิเสมอ ทำให้ชื่ออย่าง `Subaru Natsuki` ไปได้รูปของ `Natsuki Kenichi` และเมื่อค้นไม่เจอจะจำค่าว่างไว้ ทำให้กดซ้ำก็ไม่ค้นใหม่ ปัจจุบันระบบให้คะแนนความตรงกันของชื่อ (ชื่อตรงกัน > ขึ้นต้นด้วย > มีคำนั้นอยู่ > มีบางคำ) แล้วเลือกผลที่มีรูปและคะแนนสูงสุด อีกทั้ง **ไม่จำผลที่ล้มเหลว** จึงลองใหม่ได้ทุกครั้งที่แตะชื่อ พร้อมข้อความบอกสาเหตุว่าไม่พบในวิกิหรือปิดสวิตช์โหลดรูปอยู่

## 4. หน้าตั้งค่าและหน้าจอเปิดแอป

### 4.1 การจัดกลุ่มหน้าตั้งค่า

หน้าตั้งค่าแบ่งเป็น 5 กลุ่มการ์ด: **ตัวอักษร** (ฟอนต์, ขนาด, ระยะบรรทัด, ความกว้าง, ระยะขอบบน พร้อมกล่องตัวอย่างที่เปลี่ยนตามที่เลือกทันที), **ธีม**, **การอ่าน** (โหมด, ย่อหน้า, ไฮไลต์, เลื่อนตาม, แตะอ่าน), **เสียงอ่าน** (เสียง, ความเร็ว) และ **อื่น ๆ** (รูป, กันจอดับ, ตารางชื่อตัวละคร) เพื่อให้ตัวเลือกที่เกี่ยวข้องกันอยู่ติดกันและหาได้เร็วขึ้น

### 4.2 หน้าจอเปิดแอปและเลขเวอร์ชัน

ทุกครั้งที่เปิดแอปจะเห็นหน้าจอเปิดพร้อมโลโก้ ชื่อแอป และเลขเวอร์ชัน (นิยามที่ `APP_VERSION` ใน `app.js`) แล้วเฟดเข้าสู่หน้าอ่านเองภายในประมาณหนึ่งวินาที ถ้าฐานข้อมูลหรือการนำเข้าไฟล์มีปัญหา หน้าจอนี้ปิดให้เสมอ ไม่ค้าง เลขเวอร์ชันเดียวกันแสดงซ้ำที่ด้านล่างของหน้าตั้งค่าเพื่อตรวจว่าเครื่องที่ติดตั้งไว้ได้อัปเดตแล้วหรือยัง

## 5. สำหรับผู้พัฒนา

### 5.1 โครงสร้างไฟล์

| ไฟล์ | หน้าที่ |
| --- | --- |
| `index.html` | โครงหน้าแอป หน้าอ่าน หน้าตั้งค่า และไดอะล็อกทั้งหมด |
| `app.js` | ตรรกะทั้งหมด: IndexedDB, การนำเข้า, โหมดอ่าน, TTS, การ์ดตัวละคร |
| `style.css` | ธีม โหมดพลิกหน้า ความปลอดภัยของ safe area และกฎการแสดงผลทั้งหมด |
| `service-worker.js` | precache ไฟล์แอปและ `characters.json`, กลยุทธ์ network-first สำหรับไฟล์เปลือก |
| `manifest.webmanifest`, `icons/`, `fonts/` | ข้อมูล PWA, ไอคอน และฟอนต์ SIL OFL |
| `characters.json` | ดัชนีตัวละครที่สร้างจากวิกิ (รูป ชื่อ สีฝ่าย) |
| `tools/bump-version.py` | อัป `APP_VERSION` และ `CACHE_NAME` พร้อมกัน |
| `tools/build-characters.py` | สร้าง `characters.json` จากหน้า Characters |

ไม่มี build step ไม่มี package manager และไม่มี dependency

### 5.2 GitHub Pages

เพื่อไม่เผยไฟล์ของส่วนขยาย ให้สร้าง repository แยกที่มีเฉพาะเนื้อหาโฟลเดอร์นี้ (วาง `index.html`, `app.js` และไฟล์ประกอบไว้ที่ root) จากนั้นเปิด **Settings → Pages → Build and deployment**, เลือก **Deploy from a branch**, เลือก `main` และ `/(root)`, แล้วกด **Save** เปิด URL HTTPS ที่ Pages แสดงใน Safari

ถ้าเก็บ PWA ไว้ใน repository อื่นใต้ path `mobile-reader/` ต้องตั้ง workflow ให้ deploy เนื้อหาในโฟลเดอร์นี้เป็น artifact ของ Pages การเลือก `/root` จาก branch จะไม่เผยแพร่โฟลเดอร์ย่อยโดยตรง

**ความเป็นส่วนตัว:** การตั้ง repository เป็น private ไม่ได้ทำให้ URL ของ GitHub Pages เป็นส่วนตัวอัตโนมัติในแผนทั่วไป หน้า Pages อาจเปิดให้คนทั่วไปเข้าถึงได้ แม้ repository เป็น private ขึ้นอยู่กับแผนและการตั้งค่า Pages ดังนั้นแยก repository เฉพาะ PWA และอย่า commit ไฟล์สำรอง JSON หรือบทแปลลง GitHub ตรวจ setting ความเป็นส่วนตัวของ Pages ก่อนเผยแพร่

ดู [การตั้งค่าแหล่งเผยแพร่ GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site) และ [การเปลี่ยนการมองเห็นของ GitHub Pages](https://docs.github.com/en/enterprise-cloud@latest/pages/getting-started-with-github-pages/changing-the-visibility-of-your-github-pages-site)

### 5.3 การนับเวอร์ชัน

ทุกครั้งที่มีการแก้ไข ไม่ว่าจะเป็นฟีเจอร์ การแก้บั๊ก หรือข้อความ (รวมถึงเอกสารนี้) จะอัปเลขเวอร์ชันก่อน commit เลขตัวท้าย (patch) วิ่ง 0 ถึง 9 แล้วจึงขึ้นเลขกลาง (minor): `1.4.0 … 1.4.9 → 1.5.0` ใช้ `python3 tools/bump-version.py patch` (หรือ `minor` / `major`) ซึ่งอัปเดต `APP_VERSION` ใน `app.js` และ `CACHE_NAME` ใน `service-worker.js` ไปพร้อมกัน จึงไม่มีทางที่สองไฟล์นี้หลุดจากกัน เลขเวอร์ชันแสดงบนหน้าจอเปิดแอปและท้ายหน้าตั้งค่า กติกาเต็มอยู่ใน `AGENTS.md`

### 5.4 เช็กก่อน commit

- `node --check app.js` และ `node --check service-worker.js`
- ทุก `byId("…")` / `document.getElementById("…")` มี element อยู่ใน `index.html`
- เสิร์ฟโฟลเดอร์นี้ (`python3 -m http.server 3000 --bind 0.0.0.0`) แล้วยืนยันว่า `index.html`, `app.js`, `style.css`, `service-worker.js` ตอบ 200
- ไม่มีเบราว์เซอร์ในเครื่อง cloud พฤติกรรมจริงบนจอต้องยืนยันบนมือถือ

### 5.5 การดูแลเอกสารนี้

- เพิ่มฟีเจอร์/แก้บั๊กแล้ว ให้เขียนในหัวข้อที่ตรงกับหมวด (1–5) หรือเพิ่มหัวข้อย่อยถัดเลขในหมวดนั้น ไม่ใช่ต่อท้ายไฟล์
- หัวข้อที่ล้าสมัยให้แก้หรือลบในที่เดิม ไม่ทิ้งคำอธิบายเก่าไว้คู่กับของใหม่
- ถ้าเพิ่มหมวดใหม่ ให้เติมในสารบัญหมวด (รายการหัวข้อ `##`) และคงลำดับเลขให้อ่านตามการใช้งานจริง
